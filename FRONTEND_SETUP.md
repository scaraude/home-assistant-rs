## Build & Deployment Workflow

### Development (on Mac)

1. **Start Backend** (in one terminal):
   ```bash
   # If running locally for development
   cargo run
   ```

2. **Start Frontend Dev Server** (in another terminal):
   ```bash
   cd frontend
   npm run dev
   ```
   - Opens at `http://localhost:5173`
   - Hot-reload enabled
   - API requests proxied to `localhost:8082`

### Production Build

```bash
# 1. Build frontend (creates static files)
cd frontend
npm run build

# 2. Build Rust backend for Raspberry Pi
cd ..
cargo build --release --target aarch64-unknown-linux-musl

# 3. Build Docker image
docker compose build home-assistant-rs

# 4. Deploy to Raspberry Pi
docker compose up -d
```

## API Integration

The frontend consumes these existing endpoints:

- `GET /api/sensors` → Returns `string[]` of sensor IDs
- `GET /api/readings?sensor_id=<id>&hours=<hours>` → Returns sensor readings

**Data Flow:**
1. App loads → Fetch all sensors
2. For each sensor → Fetch 24h of readings
3. Render SensorCard with current values + graph
4. Poll every 15 seconds for updates

## Troubleshooting

### Frontend Won't Build

```bash
cd frontend
rm -rf node_modules package-lock.json
npm install
npm run build
```

### Backend Won't Serve Static Files

Check that:
1. `static/` directory exists with `index.html` and `assets/`
2. Backend is running from project root (not `src/`)
3. File permissions allow reading `static/` files

### API 404 Errors

Verify:
1. Backend is running on port 8080 (Docker) or 8082 (local)
2. Database has sensor data: `sqlite3 data/home_assistant.db "SELECT * FROM temperature_readings LIMIT 5;"`

### Charts Not Rendering

Check browser console for:
1. Chart.js loading errors
2. Data format issues (timestamps should be Unix epoch in seconds)
3. Network errors fetching readings

## Performance Optimization

The frontend is already optimized for Raspberry Pi:

- **Vite Build**: Minified, tree-shaken, code-split
- **Chart.js**: Only registers used components (not full library)
- **Polling**: 15s interval balances freshness vs. load
- **Caching**: Static assets cached for 1 hour

### To Reduce Bundle Size Further

1. **Use uPlot instead of Chart.js** (~200 KB savings):
   ```bash
   npm uninstall chart.js chartjs-adapter-date-fns
   npm install uplot
   ```

2. **Lazy load Chart.js**:
   ```typescript
   const Chart = await import('chart.js');
   ```
